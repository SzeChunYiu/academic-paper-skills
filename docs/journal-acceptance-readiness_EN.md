# Journal Acceptance Readiness: Editors, Reviewers, Routing, and Revision

Journal acceptance is not controlled by one editor, one reviewer, or one persuasive cover letter. A more realistic model is a sequence of gates:

```text
scientific validity/integrity
-> exact journal and article-type fit
-> editorial triage
-> editor/expertise routing
-> external review
-> editor synthesis
-> revision closure
-> final reporting/compliance
```

The package therefore optimizes **decision readiness**, not an acceptance probability.

## 1. What editors actually control

Editors are central because they often decide:

- whether a paper is in scope and mature enough for review;
- whether its contribution is important under the journal's actual publication objective;
- who handles the manuscript;
- which reviewers and specialist expertise are needed;
- how conflicting reviewer reports should be weighed;
- which concerns are essential for revision;
- whether a revised manuscript closes those concerns;
- whether a scientifically sound manuscript is still a poor fit for the target.

This makes editorial triage and synthesis critical acceptance stages, but it does not mean authors should target an editor's personality.

## 2. Public editor identities: the allowed use

Public editor information can be useful when it answers a professional routing question:

- Which editorial team/section covers this science?
- Does the journal have expertise in the paper's domain and methods?
- Is the manuscript interdisciplinary enough to require multiple expertise lenses?
- Does the submission system permit authors to suggest/request an editor?
- Is a possible editor conflicted?

Use official journal editor/board pages first, then ORCID/institutional/publication records only as needed to verify professional expertise.

Do **not** build profiles of:

- editor leniency or harshness;
- inferred acceptance propensity;
- personality or ideology;
- citation preferences;
- presumed reviewer friendships;
- demographic characteristics as persuasion variables.

Editor identity is routing metadata, not a persuasion target.

## 3. Multi-editor desk preflight

Desk decisions involve some subjective judgment, especially around novelty, priority, breadth, and interest. One mock editor is therefore too fragile.

Before submission, run independent lenses:

1. **Scope/article type** — does this paper belong here?
2. **Contribution/positioning** — is the actual advance clear and fairly situated?
3. **Evidence maturity** — is the scientific case ready for reviewer time?
4. **Readership/objective** — does it meet the target's explicit importance/interest/utility criterion?
5. **Routing clarity** — are domain, methods, evidence class, and required reviewer expertise obvious?

Freeze each lens before synthesis. Do not count votes. The strongest valid desk-rejection reason is the item to repair.

## 4. Reviewer expertise coverage

For every headline claim, identify what expertise is required to evaluate it:

```text
domain science
study design / causal identification
statistics
computation / ML
measurement / instrumentation
imaging / assay
clinical / translational / policy context
resource/data stewardship
reproducibility
```

If the journal permits reviewer suggestions, suggest independent experts whose combined coverage matches the manuscript. Do not suggest people because they are expected to be favorable.

## 5. Cover letter: routing aid, not advertising

A strong cover letter should quickly communicate:

- what the paper establishes;
- why it fits the exact journal;
- what is genuinely new or important under that journal's public criteria;
- any related/concurrent submission or confidential handling issue the editor needs to know.

Do not use author prestige, flattery, unsupported “breakthrough” claims, or strategic citations to named editors.

The manuscript must carry the scientific case itself.

## 6. Revision is part of acceptance engineering

After peer review, do not optimize the response letter for politeness or length. Optimize the **revision delta**.

Each blocking concern should have a resolution test and one of these routes:

- add decisive evidence;
- reanalyse existing evidence;
- correct an error;
- expose/clarify evidence that was already present;
- expand missing reasoning;
- redesign a weak or misleading figure/table;
- narrow the claim;
- remove the claim;
- change target/article type.

A reviewer request is not automatically mandatory. The editor should decide which concerns map to the journal's publication criteria and which are optional enrichment.

## 7. Retargeting is not failure

A scientifically sound paper may still be wrong for a particular venue because it is too specialist, insufficiently broad for that journal, outside scope, or the wrong article type.

A target ladder should compare:

```text
scope
contribution class
article type
novelty/importance/utility threshold
readership
methods/reporting compatibility
editorial expertise coverage
practical constraints
```

Do not rank journals only by impact factor or prestige.

## 8. Irreducible uncertainty

Even a decision-ready manuscript can be rejected because of factors authors cannot legitimately engineer:

- overlapping work that has just appeared or been accepted;
- competition among several strong submissions;
- reviewer availability;
- editor disagreement on soft priority criteria;
- confidential information unavailable to authors;
- legitimate editorial discretion.

Keep this bucket separate from repairable manuscript problems. Do not respond to every rejection with more experiments, more hype, or more personalized editor targeting.

## 9. Package behavior

The academic-paper pipeline now tracks:

```text
science/integrity
scope
contribution/novelty
readership/objective
evidence maturity
methods/statistics/reporting
visual evidence
editorial routing
reviewer coverage
revision closure
compliance
uncontrollable editorial context
```

It may return `decision_ready_for_submission_to_target`, but never a numeric probability of acceptance.

When a journal permits editor suggestions, the machine-checkable routing profile requires:

- current policy evidence;
- official editor/board sources;
- professional expertise evidence;
- conflict status;
- explicit permitted use.

Fields such as `acceptance_probability`, `leniency_score`, personality, ideology, or citation preference are rejected by the validator.

## Bottom line

The practical acceptance strategy is:

**make the science valid → choose the right journal → make the contribution instantly recoverable → expose decisive evidence and boundaries → make the paper easy to route to the right expertise → survive independent review → let the editor adjudicate real blockers → revise the manuscript until those blockers are actually closed.**

That is acceptance engineering. Personalized editor manipulation is not.
