# Editor expertise and routing

> Boundaries and workflow for using public editor information to improve fair manuscript routing without targeting or manipulating individuals.
>
> Last reviewed: 2026-08-29.

## Core rule

Public editor identities are useful as **professional routing metadata**, not as psychological targets.

Use editor information to answer:

> Does this journal have an editor/team/section with the professional expertise needed to understand and route this manuscript fairly?

Do **not** ask:

> Which editor is easiest to persuade or most likely to accept this paper?

## Allowed public information

Prefer official journal sources first:

- editor name;
- journal role;
- section/team;
- publicly stated handling scope;
- professional research background;
- institutional affiliation;
- ORCID or publication record when needed to verify subject expertise;
- explicit submission-system rules about requesting/suggesting editors;
- public competing-interest rules.

Use only information relevant to professional editorial routing.

## Prohibited profiling

Do not infer or use:

- personality;
- political/religious beliefs;
- demographic identity as a persuasion variable;
- private social relationships;
- leniency/harshness labels;
- acceptance propensity estimated from a small public sample;
- presumed citation preferences;
- personal social-media behavior;
- inferred reviewer friendships;
- private editorial communications;
- speculative handling history.

Do not search for personal information that is unnecessary for scientific routing.

## Editor-routing profile

When a named target makes editor routing useful, build an ephemeral target-specific profile:

```text
Exact venue
Article/content type
As-of date
Official editor/team source

Manuscript domain tags
Methods/evidence tags
Contribution class
Required reviewer expertise

Editor/team candidate
Official role
Official section/team
Public professional expertise supporting fit
Source
Conflict status
Submission-system editor suggestion allowed? yes/no/unknown
Routing fit: strong / plausible / weak / conflict / unknown
Notes
```

Do not store a permanent editor-personality or acceptance-history database.

Editor lists change; resolve them live for submission-critical work.

## Journal-level expertise coverage map

Before thinking about one person, map the journal's coverage at the **team/section level**.

Ask:

1. Is there a clearly relevant subject team or section?
2. Does the journal publicly describe handling expertise for this contribution class?
3. Does the manuscript span multiple expertise domains that may require co-handling or specialist reviewers?
4. Is the work so far outside the visible expertise map that target fit should be reconsidered?
5. Are the manuscript's title/abstract/keywords clear enough for the editorial office to route it correctly?

Weak coverage does not prove rejection. It is a routing-risk signal.

## Expertise decomposition

Map the manuscript into evaluation domains rather than only topic keywords.

Example:

```text
Domain science
Study design / causal identification
Measurement / instrumentation
Statistics
Computation / ML
Imaging / assay
Clinical or policy context
Resource/data stewardship
Reproducibility
```

A manuscript can be topically matched but technically difficult to route if one decisive claim depends on expertise not obvious from the title/abstract.

## Routing-clarity repair

When routing is ambiguous, improve the manuscript/submission metadata rather than adding internal project language.

Possible repairs:

- more precise title;
- clearer abstract contribution sentence;
- explicit study design;
- accurate field/method keywords;
- clear article-type selection;
- clear description of the decisive evidence class;
- concise cover-letter statement of the manuscript's domain and contribution;
- subject/category selection in the submission portal.

Do not insert editor names into the manuscript.

## Suggesting an editor

Only suggest/request an editor when the exact current journal workflow explicitly permits it.

If permitted:

1. choose by subject/method expertise;
2. check obvious conflicts under the journal's rules;
3. explain fit factually if the submission system asks;
4. provide multiple qualified options when the system requests multiple names;
5. let the journal make the assignment.

Do not select based on perceived favorability.

For example, current PLOS ONE submission instructions ask authors to recommend 2–5 Academic Editors qualified to handle the submission. This is a routing function, not an invitation to select friendly editors.

## Editor exclusions

If the exact journal permits editor exclusions, use them only for legitimate reasons such as:

- competing interest;
- recent close collaboration;
- institutional conflict;
- direct scientific dispute creating a credible conflict under journal policy;
- other journal-recognized conflict.

Do not exclude an editor merely because they may be scientifically critical.

## Public editor expertise versus target fit

Editor expertise can reveal useful target information:

- a multidisciplinary journal may have a dedicated team for the manuscript's domain;
- a board-based journal may organize Academic Editors by subject taxonomy;
- a specialist journal may have strong methodological coverage but a narrower contribution objective;
- a paper spanning two fields may need a target with visible cross-domain handling capacity.

But editor expertise does not override official aims/scope or publication criteria.

## Reviewer expertise coverage

Use the same decomposition to anticipate reviewer needs.

For each headline claim ask:

```text
What expertise is required to assess this claim?
Can one reviewer reasonably cover it?
What methods/statistical specialty is needed?
What domain specialty is needed?
Does a cross-disciplinary claim need an additional lens?
```

If reviewer suggestions are permitted, propose independent reviewers by coverage rather than expected recommendation.

## Cover letter boundary

A cover letter may say that the manuscript sits at the intersection of specific scientific areas and explain why that fits the journal.

It should not say:

- "Editor X will appreciate this because...";
- "we cite Editor X's work extensively";
- "this aligns with Editor X's personal interests";
- flattering statements about an editor's career;
- claims that a particular editor should accept the work.

If the portal explicitly asks for an editor recommendation, put the factual recommendation there or in the designated field.

## Routing uncertainty

If official editor/team information is incomplete or stale:

- mark routing as `unknown`;
- use official scope/section information;
- research current editor pages;
- do not guess a likely handling editor;
- do not build acceptance advice around an uncertain identity.

## Output contract

For target-specific submission support, return an **editorial routing brief** only when useful:

```text
Journal/team coverage
Manuscript domain + methods tags
Likely expertise needed
Public editor/team candidates if relevant
Conflict checks
Whether editor suggestions are permitted
Routing ambiguity
Submission metadata repair
```

Keep this separate from manuscript prose.

## Research basis

Current official examples reviewed 2026-08-29:

- Nature Communications publicly lists professional editor teams, subject coverage and scientific backgrounds; its editorial process assigns a primary editor who assesses novelty, impact, scope, advance and readership interest.
- PLOS editor resources explicitly prioritize subject-matter expertise and conflict avoidance when assigning Academic Editors.
- PLOS ONE currently asks submitting authors to recommend 2–5 qualified Academic Editors and permits opposed editors/reviewers with reasons.
- Nature Portfolio reviewer guidance identifies expertise as the primary consideration in reviewer selection.
- Communications-series editorial-board pages state that board members handle manuscripts within areas of expertise.

These examples support expertise-based routing. They do not support individualized persuasion or predicting an editor's decision.
