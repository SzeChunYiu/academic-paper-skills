# Section: Abstract

The abstract is a mini-paper:

`context/problem -> gap/objective -> approach -> key results -> implication`

It should answer:

1. What question was addressed?
2. How was it addressed?
3. What was found?
4. Why should anyone care?

Some journals require a strict abstract format. Follow the journal if it conflicts with the generic pattern. (See the loaded `journal/*.md` fragment for journal-specific constraints.)

## Standalone terminology and equation gate

The abstract must be self-contained. A definition in the body does not satisfy
first use here. Expand or semantically define non-universal abbreviations,
paper-defined terms, and symbols locally. Replace internal labels with the
reader-facing scientific object unless the label is necessary, stable, and
immediately explained. Never invent an expansion.

Resolve the exact target before enforcing layout. For an unknown target, prefer
continuous prose and verbal or inline mathematics. Retain a display equation
only when it is central, target-permitted, more intelligible than inline wording,
locally defined, and interpreted in adjacent prose. A short or repeated abstract
display equation is a review signal because it can create unnecessary vertical
breaks and notation load.

For IEEE, apply the current official self-contained single-paragraph rule that
excludes abbreviations and mathematical equations.

## Polishing priorities

- Cut sentences that summarize background that the title already implies.
- Make the gap and the contribution one short, locatable sentence each.
- The last sentence should state significance, not repeat the result.
- Reduce notation until the question, result, and boundary remain recoverable in
  one cold read.
- Do not let a polished internal label remain unexplained merely because it is
  consistent.
